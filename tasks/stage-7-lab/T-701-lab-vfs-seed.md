## Goal

In-memory copy of everything `build-lab.sh` creates.

## Steps

- `vfs.ts`: path → `{ content: Uint8Array | string, mode, owner, group, mtime }`; cwd handling.
- `seedLab.ts`: `auth.log` from the script's lines; four 2 MiB random installers with real SHA-256 in `vendor_hashes.txt`, then append `injected-payload` to one at random; `etc/`, `home/deploy/.ssh` with the script's modes.
- Reset = call `seedLab()` again.

## Files

- `app/lib/terminal/vfs.ts`
- `app/lib/terminal/seedLab.ts`
- `app/lib/terminal/labSeed.json` (generated by `npm run lab:seed`)
- `shared/labScript.ts` (parser), `scripts/lab-seed.ts` (generator CLI)
- `tests/unit/terminal-vfs.test.ts`, `tests/unit/terminal-seed.test.ts`

## Acceptance criteria

- [x] File tree matches a real `build-lab.sh` run.

## Notes

- `build-lab.sh` writes the Lab B answer to a hidden file `~/secplus-lab/.answer-lab-b` (line 150). Don't create it in the virtual file system, or `ls -la` and `cat` would give the answer away. Keep the tampered filename in memory for the Lab B check.

- Done. The text files, directories and modes are not copied by hand: `shared/labScript.ts` parses `build-lab.sh` (heredocs, `printf`/`touch` redirects, `chmod`, the brace `mkdir -p`, the Lab B loop) and `npm run lab:seed` writes `app/lib/terminal/labSeed.json`. Any line it does not understand is an error with `build-lab.sh:<line>`, so a script change fails loudly. `tests/unit/terminal-seed.test.ts` checks the committed JSON against a fresh parse and the CLI (drift), checks key files against the script's own heredoc lines, and, where `bash` and `sha256sum` exist (CI), runs the real script in a temp `$HOME` and compares the whole tree (paths, kinds, modes, sizes, text contents, hash-file order, the one mismatch). On macOS the test swaps `shuf -n1` for `sort -R | head -n1`.
- `seedLab()` is async (Web Crypto `subtle.digest`) and returns `{ vfs, tamperedFile }`. `.answer-lab-b` is not created; the parser records its name only so the tests can assert it stays out. Note that `shared/lab.ts` (Lab B step) still tells the student to `cat ~/secplus-lab/.answer-lab-b`: right for the downloaded script, but in the browser terminal it prints "No such file or directory". T-706 should word the in-browser Lab B step differently (check by entering the filename).
- Ownership and time follow LLD §13.2's `ls -l` example: every seeded node is `root root` with mtime `Nov  3 09:14` (UTC, 2026), and the lab user's home is `/root` (`LAB_USER`, `LAB_HOME`, `LAB_MTIME` in `seedLab.ts`). A real run shows the student's own user and the build time; T-707 fixtures need to normalise those columns.
- Permission bits are stored and formatted (`octalMode`, `formatMode`) but not enforced: in the real lab the student owns every file. `Vfs.list()` sorts by byte order; `ls` in a UTF-8 locale collates differently (ignores leading dots and case), which is for T-703 to handle if fixtures need it.
